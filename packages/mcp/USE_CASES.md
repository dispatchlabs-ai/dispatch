# MCP use cases

- An MCP client discovers configured agents and starts a conversation through the existing host.
- A client continues a retained Web, terminal or MCP conversation without a second execution owner.
- A caller observes live progress, native completion, tool results and retained artifacts; an interrupted wait does not cancel work.
- A caller explicitly stops a conversation and inspects its retained outcome.
- An agent asks another configured agent through MCP and receives the answer using stable conversation and submission identities.
- An agent sends a native assignment through MCP, finishes its current turn, and resumes when the recipient's answer arrives automatically as a new input.
- A caller discovers permitted peers, inspects native message receipts, or waits for related handoffs without polling or resubmitting work.
- An operator exposes these operations through local stdio or authenticated Streamable HTTP with installation-level authority.

WebMCP, per-user grants, OAuth enrollment, administration and arbitrary host file access are outside this package.
