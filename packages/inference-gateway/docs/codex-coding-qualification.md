# Codex Mac app coding qualification — October 21, 2026

A local Codex task read files, edited Python, ran commands, continued the same
conversation and resumed after an app quit/reopen through the Dispatch gateway.
All 13 successful inference requests matched central gateway logs: ten ended in
tool use and three completed the user turns. Installation names, account and
request identifiers, filesystem paths and private logs are omitted from this
public record.

This extends the [text experiment](codex-probe.md). It qualifies the observed
coding workflow through a temporary adapter, not a production client integration
or the complete Responses protocol.

## Setup and execution

The app's bundled Codex was `0.163.0-alpha.10.2`. The task used `gpt-6-astra`,
`xhigh`, Full Access (`danger-full-access`) and `approval_policy = "never"`.
The desktop account remained signed in throughout; no account switch was
performed. The route was:

```text
ChatGPT Mac app / local Codex
  -> client loopback :8789
  -> temporary SSH tunnel to an operator Mac
  -> Responses/Pi adapter using an enrolled AWS identity
  -> HTTPS inference gateway
  -> gateway's OpenAI API connection / gpt-6-astra
```

Provider credentials stayed on the gateway. The deployed ECS service was
unchanged. The probe used SSE with stateless conversation replay and no direct
provider fallback. Local tools executed on the client Mac through Codex's custom
`functions.exec` tool, including its shell and patch tools.

The disposable fixture was a receipt calculator with incorrect totals and unit
counts. The [final source and input](fixtures/codex-coding/README.md) are saved
beside this record. These were interactive commands and source inspection, not
an automated test suite.

| Turn | Work actually completed | Observed output |
| --- | --- | --- |
| Initial task | Read the instructions, Python and CSV; account for quantities and decimal prices; run the program | `{"total": "9.75", "units": 6}` |
| Follow-up | Recall a phrase kept only in conversation; add `--format text`; run both formats | JSON total `9.75`, units `6`; text `total 9.75` / `units 6` |
| Resume after app restart | Reopen the same task, recall the phrase, add two stamps at `0.20`, run both formats | JSON total `10.15`, units `8`; text `total 10.15` / `units 8` |

The task and replies were inspected in the app. The same task survived restart,
and its saved conversation recorded the effective settings and actual tool
results. Account settings were checked before and after the trial.

## Gateway evidence

Each successful adapter completion matched a central gateway request for the
enrolled principal, connection `openai` and model `gpt-6-astra`. The ten custom
tool calls were followed by their tool results in subsequent requests. Exact
correlation identifiers and operator logs are retained privately.

The adapter logs request IDs, counts, selected routing, usage and error fields;
it does not log raw prompts, responses or tool contents. A reproduced experiment
must establish its own request correlation rather than reuse this result.

## Limits and cleanup

Automatic task-title generation failed with HTTP 400 `unsupported_probe_request`
at `text.format.type`. The adapter rejects structured output, so the task retained
its original prompt as its title. The coding request and all three user turns
completed successfully after that failure.

The implementation translates function and custom tools, namespace names,
`additional_tools`, tool call IDs/results and reasoning payloads. The live trial
exercised custom tools. It returned no reasoning items and reported zero reasoning
tokens, so encrypted reasoning replay remains unqualified even though `xhigh`
was forwarded. Images, compaction, function-call execution, cancellation, provider
failures, long sessions and other app features were not qualified. Native
assistant text item IDs are regenerated by the probe. See OpenAI's
[gateway compatibility requirements](https://learn.chatgpt.com/docs/enterprise/gateway-compatibility).

The temporary provider selection, token, backup files, adapter and SSH forward
were removed. Concurrent app configuration was preserved. The app was restarted
with its original provider, model, reasoning, Full Access and approval defaults;
both loopback ports were confirmed closed. No persistent workstation service
was added.

Employee SSO, individual attribution and budgets, direct workstation access,
subscription pooling, resets and central failover were outside this trial.
Source review and `nix develop --command npm run check` passed. No automated
tests were added or run under the repository's testing policy.
